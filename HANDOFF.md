# 3DS Model Viewer — Project Handoff

This document captures the full context of the project for Claude Code sessions and human contributors picking up the work mid-stream.

---

## Project goal

Build a homebrew 3DS application that displays a 3D model on the top screen and lets the user rotate it using the circle pad. This is a learning/exploration project, not a polished release.

---

## Dev environment

- **Machine:** MacBook (macOS, personal machine)
- **IDE:** Cursor
- **Toolchain:** devkitPro with devkitARM, libctru, citro3d, picasso — all installed via `dkp-pacman -S 3ds-dev`
- **Toolchain location:** `/opt/devkitpro`
- **Target hardware:** New 3DS LL (Japanese unit, region-switched to English, CFW installed)
- **Deployment:** `3dslink` over WiFi — push `.3dsx` directly to the 3DS without touching the SD card

### Environment variables (in `~/.zshrc`)

```bash
export DEVKITPRO=/opt/devkitpro
export DEVKITARM="${DEVKITPRO}/devkitARM"
export PATH="${DEVKITPRO}/tools/bin:${PATH}"
```

### Build & deploy workflow

```bash
make                                          # produces model-viewer.3dsx
3dslink -a <3DS_IP> ./model-viewer.3dsx      # pushes to 3DS over WiFi
```

The 3DS must have the Homebrew Launcher open with the network receiver active (press Y in hbmenu) before running `3dslink`. Auto-discovery often fails — always pass `-a <IP>` explicitly.

## Key technical context

### Graphics pipeline

- The 3DS GPU is the **PICA200** — it does not use OpenGL or GLSL
- Vertex shaders are written in **PICA200 shader assembly** (`.v.pica` files), compiled by the `picasso` tool (included in devkitPro)
- The graphics library is **citro3d**, which wraps the PICA200 for matrix math, vertex buffers, uniforms, and draw calls
- Shader `.v.pica` files are compiled automatically as part of the `Makefile` build system in the examples — follow the same pattern

### Screen setup

- Top screen framebuffer dimensions are **240×400** (not 400×240) — the screen is landscape but the framebuffer is rotated
- Account for this in the projection matrix via `Mtx_PerspTilt`
- Render target is created explicitly, targeting `GFX_TOP` / `GFX_LEFT`
- The bottom screen is not used in this project

### Circle pad input

```c
circlePosition pos;
hidScanInput();
hidCircleRead(&pos);
// pos.dx and pos.dy are signed integers, roughly -150 to +150
angleY += pos.dx * 0.0003f;
angleX -= pos.dy * 0.0003f; // negate so up=tilt-up
```

### Vertex format

```c
typedef struct { float position[3]; float color[3]; float normal[3]; } vertex;
```

Models are baked into the binary as `const vertex model_vertices[]` with a companion `int model_vertex_count`. See `source/model.h` (regenerated by the asset pipeline — not checked in).

### MVP matrix pattern

```c
C3D_Mtx projection, modelView;

// Projection — swapped aspect ratio due to framebuffer rotation
Mtx_PerspTilt(&projection, C3D_AngleFromDegrees(80.0f), C3D_AspectRatioTop, 0.01f, 1000.0f, false);

// ModelView — updated each frame
Mtx_Identity(&modelView);
Mtx_Translate(&modelView, 0.0f, 0.0f, -2.0f, true);
Mtx_RotateX(&modelView, angleX, true);
Mtx_RotateY(&modelView, angleY, true);
```

### Basic render loop

```c
while (aptMainLoop()) {
    hidScanInput();

    circlePosition pos;
    hidCircleRead(&pos);
    angleY += pos.dx * 0.0003f;
    angleX -= pos.dy * 0.0003f;

    C3D_FrameBegin(C3D_FRAME_SYNCDRAW);
        C3D_RenderTargetClear(target, C3D_CLEAR_ALL, CLEAR_COLOR, 0);
        C3D_FrameDrawOn(target);
        sceneRender();
    C3D_FrameEnd(0);
}
```

## Asset pipeline

Models are not loaded at runtime — they are converted to C arrays at build time.

### High-poly OBJ → decimated OBJ (Blender headless)

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background \
  --python tools/decimate_obj.py -- input.obj output.obj 0.05
```

`0.05` = 5% of original faces. Targets roughly 3,000–5,000 triangles for comfortable 3DS budget.

### OBJ → C header

```bash
python3 tools/obj_to_c.py model.obj R G B > source/model.h
```

- Auto-centres and scales to unit cube
- Uses OBJ normals when present; falls back to per-face normals
- Fan-triangulates quads and n-gons
- `R G B` is the base colour (floats in [0,1])

## Planned next steps

### SD card model picker (future)

The eventual UX: a file browser on the 3DS that reads `.bin` files from `sdmc:/models/`, loads the selected one into the VBO, and renders it. The Python tools become an **offline converter** (OBJ → compact binary), and the 3DS app gains a **runtime loader** (`fread` into linearAlloc).

Key design decision: use a simple custom binary format (raw interleaved floats + a small header) rather than parsing OBJ text at runtime. Parsing OBJ on a 133MHz ARM11 is slow; loading pre-converted binary is a near-instant `fread`.

### Remaining rendering work

- Experiment with lighting direction (currently fixed at camera-forward `{0, 0, -1}`)
- Consider a second light or ambient term tweak for better depth on organic models
- Optionally: zoom control on the D-pad or +/- buttons
